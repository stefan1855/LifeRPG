# LifeRPG 2.3.0-rc.2 原生 DPI 验收

日期：2026-10-31。结论：本机原生 Windows 125%、150%、175% 的稳定布局、动态缩放后的窗口约束、重启和 Win32 输入测试通过。**系统已恢复为 100% / 96 DPI，隔离测试程序已退出。**

## 实测结果

本机只有一个 1920×1080 显示器。实际修改 Windows 显示缩放，没有向 WebView2 传入 `--force-device-scale-factor`，也没有使用 CDP 设备尺寸模拟。以下 DPI 来自 `GetDpiForWindow`，DPR 同时核对为 1.25、1.5、1.75。

| Windows 缩放 | 实际窗口 DPI | 主窗口 CSS 视口 | 10 页检查 |
|---|---|---|---|
| 125% | 120 | 1460 × 800 | 通过 |
| 150% | 144 | 1250 × 656 | 通过 |
| 175% | 168 | 1068 × 554 | 通过 |

- 30 个页面状态：页面容器横向溢出不超过 2 CSS 像素的取整容差；可见按钮、输入框和选择框没有横向越过视口；没有错误提示。较矮窗口使用纵向滚动，不要求所有内容同时出现在首屏。
- 每档通过 Win32 消息完成主窗口→挂件→新增任务弹窗→字符输入→连续两次保存点击→胶囊→挂件；数据库核对只保存一条。
- 每档重新启动程序，核对实际 DPI 和整个原生外框留在工作区内。
- 挂件和胶囊各自通过 175%→125%→175% 动态变化，窗口保持可见。主窗口通过 100%→125%→150%→175% 和返回 100%。
- 30 项后端回归通过，0 失败；2 项真实 AI 网关测试按原有条件跳过。前端生产构建、Tauri Release 构建通过。MSVC 仍有生成导入库的 linker stdout 信息警告。
- ZIP 解压后启动、设置页版本、程序哈希一致性、缓存留在隔离程序目录检查通过；出包门禁检查为 0 个 Low 完整性标签。

## 本轮发现和修复

1. **动态 DPI 变化后原生外框越出工作区。** RC1 对照中，100%→125% 切换初期外框为 `[82,0,1907,1150]`；等待 10 秒后为 `[82,0,1907,1038]`，工作区底边为 1030，仍越出 8 个物理像素。RC2 在 DPI 事件后重新计算客户区、阴影边界和工作区，调整最小尺寸、实际尺寸和位置；切换形态时也执行同一约束。
2. **175% 下设置页长路径撑宽双列网格。** 连续 3 秒采样仍为 `clientWidth=816 / scrollWidth=824`，确认属于持续布局问题。网格改为允许收缩的列，列和路径内容解除固有最小宽度，窄窗口改为单列，操作按钮允许换行。最终包按相同测试复核通过。

Windows 会依次更新 DPI、建议窗口矩形和任务栏工作区。测试等待实际状态稳定，并记录中间采样；**通过结论针对稳定后的可用状态，不代表系统切换动画的每一帧都没有临时越界。** 页面检查也等待切换动画和异步布局结束，没有放宽持续溢出的判据。

## 验收边界

- 本机 Windows 标准缩放范围只到 175%，**原生 200% 未验收**；此前的 200% 只是渲染缩放，不升级为原生结论。没有设置需要注销的自定义缩放。
- 只有一个显示器，跨显示器拖动、不同分辨率、不同任务栏位置、独立系统文字大小及最大化状态切换 DPI 未作专项验收。
- AI 真实网关、真实 MCP、系统通知最终送达、无引用图片清理仍沿用此前未完成项；本轮没有把它们标为通过。
- 极小形态动态切换 DPI 时，框架对无边框阴影的换算可能令客户区尺寸略有变化；已验证所测状态保持可见可用，本轮不承诺自定义尺寸逐像素保持。
