## 缩放测试边界

本机显示器 1920×1080，工作区 1920×1040，**Windows 原生 DPI 始终为 96（100%）**，没有修改用户显示设置。

125%、150%、200% 通过实际原生程序里的 WebView2 渲染缩放运行，并以 Win32 调整物理窗口尺寸匹配 CSS 尺寸。四档主窗口 CSS 视口分别约为 1460×920、1460×768、1264×640、948×480。鼠标坐标按实际缩放转换后投递给原生渲染窗口，实际完成了输入与保存。

这验证了缩放渲染和受限视口布局，**不能替代 Windows 原生 125%/150%/200% 的 WM_DPICHANGED、多显示器跨屏、系统字体缩放和任务栏位置变化验收**。这些项仍标记为未验收。

## 本轮发现并修复

1. 任务页窄视口下四象限和操作按钮向右溢出：改为受约束列宽、工具栏换行，窄视口单列滚动。
2. 挂件压缩高度时底部空间不足：小高度下收起辅助统计或属性，保留任务和底部操作。
3. 首次启动没有应用显示器尺寸约束：启动阶段提前应用形态尺寸，并以工作区计算可用尺寸。
4. 首启卡片无法适应较矮窗口：卡片限制高度并允许滚动，增加拖动区和隐藏入口。
5. 初始化失败仍保存损坏数据目录：先验证候选数据库，再更新便携配置。
6. 空快捷键使设置页计算属性报错：空值显示“未设置”。
7. 窄面板按钮换行后超出固定高度：按钮文字不换行，面板标题区和操作区按需换行。
8. 小窗口错误提示可能超出窗口：约束提示宽度；胶囊形态隐藏提示。
9. 图片目录读取失败可能生成缺图备份：现在明确返回失败。
10. 恢复只验证部分表：补充业务表完整性和外键检查。
11. 出包脚本增加版本格式及输出路径范围校验，卸载说明补充关闭开机自启步骤。

## 数据规模和时间

首轮 120 条记录、360 张引用图片的备份约 20.2 MB，备份 0.78 秒、恢复 2.56 秒。

最终复测备份约 51.1 MB，备份 2.45 秒、恢复 3.31 秒；所有 360 张引用图片哈希均保持一致。文件变大的原因是多轮异常/恢复测试保留了无引用图片。这是当前已知限制，不能将这组时间当作其他机器或更大图库的性能保证。
